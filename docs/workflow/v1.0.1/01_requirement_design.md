# v1.0.1 背包管理增强 — 需求设计

## 1. 需求背景

当前背包（`GetItemSummary`）仅按物品编码分组显示名称和数量，存在以下问题：

- **物品无法使用**：种子类物品（如"杂树种子"）只能查看数量，不能执行种植操作
- **物品无法丢弃**：玩家积攒了大量材料后缺少管理手段，无法主动清理不需要的物品
- **列表无序**：物品按编码分组展示，没有按类型、重要性排序，阅读体验差
- **缺少类型体系**：现有物品定义中没有「物品类型」字段，无法区分种子、材料、装备等类别

本版本目标：为背包增加物品使用（种植）、丢弃、排序能力，并建立物品类型分类体系。

## 2. 功能描述

### 2.1 物品使用（种植）

**判定条件**：物品模板中配置了 `ToEntityCode` 字段且非空，即视为可使用的种子类物品。当前可种植物品：

| 编码 | 名称 | ToEntityCode | 说明 |
|------|------|-------------|------|
| 3 | 杂树种子 | 1 | 种下后生成 code=1 的种子实体 |

**使用流程**：

1. 点击「使用」按钮
2. 弹出空闲区块选择模态框（标题为"种植 {种子名}"）
3. 模态框内展示所有空闲地块的网格列表
4. 若无空闲地块，显示提示"没有空闲的地块了"
5. 选择区块后调用种植 API（`ExecuteScript(blockId, interactionId)`，interactionId 格式为 `plant:{ToEntityCode}`）
6. 种植成功后消耗 1 个该种子物品
7. 刷新背包列表（数量 -1）和区块列表（地块显示种子）
8. 显示 Toast 提示"成功种植了 {种子名}"

**前置条件**：
- 背包中存在该种子物品（数量 >= 1）
- 至少存在一个空闲区块（EntityCode 为空且未被占用）

### 2.2 物品丢弃

**适用范围**：所有物品均可丢弃。

**丢弃流程**：

1. 点击「丢弃」按钮
2. 弹出确认模态框，显示"确定要丢弃「{物品名}」吗？"
3. 输入框预填默认值 1，最大值为当前持有数量
4. 显示"当前持有 {n} 个"提示文字
5. 点击「确认丢弃」后执行丢弃
6. 丢弃成功后：
   - 关闭模态框
   - 刷新背包列表
   - 显示 Toast 提示"已丢弃 {n} 个 {物品名}"

**丢弃规则**：
- 丢弃的物品标记 `IsDeleted = true`（软删除），不物理删除
- 丢弃不可恢复，无撤销机制
- 丢弃数量不能超过持有量，不能为 0 或负数

### 2.3 背包排序

**排序规则**（按优先级从高到低）：

1. **种子类**（有 `ToEntityCode`）排在最前
2. **材料类**排在中间
3. **其他类**排在最后
4. 同类型内按数量降序排列

**排除规则**：
- 已删除物品（`IsDeleted = true`）不参与排序和统计
- 数量为 0 的分组不显示

### 2.4 物品类型分类

**类型枚举定义**：

| 类型值 | 说明 | 排序优先级 |
|--------|------|-----------|
| Seed | 种子类 — 有 ToEntityCode，可种植 | 1（最高） |
| Material | 材料类 — 基础资源材料 | 2 |
| Equipment | 装备类 — 可穿戴的装备 | 3 |
| Consumable | 消耗品类 — 一次性使用的道具 | 4 |
| Other | 其他 | 5（最低） |

**现有物品类型分配**：

| 编码 | 名称 | 当前状态 | 建议类型 |
|------|------|---------|---------|
| 1 | 树枝 | 已定义，无 ToEntityCode | Material（材料类） |
| 2 | 木材 | 已定义，无 ToEntityCode | Material（材料类） |
| 3 | 杂树种子 | 已定义，ToEntityCode = "1" | Seed（种子类） |

> 物品类型可在物品模板（`VariableUtility.ItemModel`）中配置，也可在 `Item` 模型上新增 `ItemType` 字段实现自动推断。

## 3. 业务规则

### 3.1 丢弃校验规则

- 丢弃数量校验：不能超过持有量，不能为 0 或负数
- 前端限制：输入框 `max` 属性设为持有量，`min` 属性设为 1
- 后端二次校验：API 层需校验丢弃数量合法性，防止前端绕过

### 3.2 种植前提条件

- 必须有空闲区块（`EntityCode` 为空且未被占用）
- 背包中必须有该种子物品（数量 >= 1）
- 种植消耗 1 个物品，从背包中标记 `IsDeleted = true`

### 3.3 操作不可逆

- 物品使用（种植）后立即从背包扣除，操作不可逆
- 物品丢弃后标记删除，操作不可逆
- 不提供撤销/恢复功能

### 3.4 物品类型与排序

- 物品类型影响排序优先级（种子 > 材料 > 其他）
- 物品类型影响 UI 显示（不同类型可使用不同图标或颜色标识）
- 同类型物品按数量降序排列

### 3.5 数据一致性

- 种植操作：种植成功后才消耗物品（先种植后扣物品）
- 丢弃操作：API 返回成功后才刷新前端列表
- 操作失败时显示错误 Toast，不修改数据

## 4. 交互流程

### 4.1 使用种子（种植）流程

```
用户查看背包 → 看到种子类物品旁有「使用」按钮
    ↓
点击「使用」
    ↓
弹出模态框，标题"种植 {种子名}"
    ├── 有空闲地块 → 显示空闲地块网格列表
    └── 无空闲地块 → 显示提示"没有空闲的地块了"（无操作按钮）
    ↓
用户点击某个空闲地块
    ↓
调用种植 API (POST /Game/ExecuteScript?blockId={id}&interactionId=plant:{ToEntityCode})
    ├── 成功 → 关闭模态框 → 刷新背包 → 刷新区块 → Toast "成功种植了xxx"
    └── 失败 → 显示错误 Toast（如"种植失败：该地块已被占用"）
```

### 4.2 丢弃物品流程

```
用户查看背包 → 看到任意物品旁有「丢弃」按钮
    ↓
点击「丢弃」
    ↓
弹出确认模态框
  ├── 标题："确定要丢弃「{物品名}」吗？"
  ├── 数量输入框：默认值 1，max = 持有数量
  ├── 提示文字："当前持有 {n} 个"
  └── 按钮：「取消」/「确认丢弃」
    ↓
用户输入数量，点击「确认丢弃」
    ↓
前端校验（数量 > 0 且 <= 持有量）
    ├── 校验失败 → 输入框标红提示
    └── 校验通过 → 调用丢弃 API
    ↓
API 返回
    ├── 成功 → 关闭模态框 → 刷新背包 → Toast "已丢弃 {n} 个 {物品名}"
    └── 失败 → 显示错误 Toast
```

## 5. 验收标准

- [ ] 种子类物品（有 `ToEntityCode`）在背包中显示「使用」按钮，其他物品不显示
- [ ] 点击「使用」后弹出模态框，展示所有空闲地块
- [ ] 无空闲地块时显示"没有空闲的地块了"提示
- [ ] 选择空闲地块后种植成功，背包中种子数量减 1，区块显示种植结果
- [ ] 所有物品在背包中显示「丢弃」按钮
- [ ] 丢弃弹窗支持输入数量，默认值为 1，最大值为当前持有数量
- [ ] 丢弃数量校验：不能超过持有量，不能为 0 或负数
- [ ] 丢弃后物品从背包消失（标记 IsDeleted），API 返回的物品列表中不再包含
- [ ] 背包列表按种子优先、材料次之、其他最后排序，同类型数量降序
- [ ] 已删除的物品不影响排序和统计
- [ ] 所有操作反馈使用 Toast 提示，不使用 alert/confirm

## 6. 非功能约束

- **前端**：Bootstrap 5.1 + jQuery，纯静态 HTML（`game.html`），暗色森林主题
- **后端**：Dapper + SQLite，Controller 返回 Json
- **交互反馈**：使用 Toast 提示（成功绿色、失败红色），不使用 `alert()`/`confirm()`
- **模态框**：使用 Bootstrap Modal 组件，居中显示，点击遮罩层可关闭
- **API 风格**：新增丢弃接口为 `POST /Game/DiscardItem`，种植复用现有 `POST /Game/ExecuteScript`
- **响应格式**：`{ success: bool, message?: string, data?: object }`
- **数据持久化**：物品删除状态通过 `SaveGame` 节流机制持久化到 SQLite
